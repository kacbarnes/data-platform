# v0.3 implementation plan: Portable contracts

## Objective

Allow one committed dataset contract to resolve its source artifacts on
different machines without embedding machine-specific absolute paths.

## Scope

### Artifact roots

- Add named artifact roots to machine-local configuration.
- Let source contracts specify an artifact-root name and a relative artifact
  path.
- Preserve explicit absolute paths temporarily for backward compatibility and
  emit a migration-oriented warning.
- Resolve paths deterministically and reject traversal outside the configured
  root unless explicitly allowed by policy.

### Contract validation

- Distinguish semantic contract validation from local artifact resolution.
- Report unknown roots, missing artifacts, and invalid relative paths clearly.
- Keep contract digests stable across machines by hashing authored YAML rather
  than resolved absolute paths.
- Record the resolved source URI and checksum in operational metadata.

### Migration

- Convert included examples and Taya contracts to named roots.
- Provide a command or documented procedure that reports contracts still using
  machine-bound paths.

## Proposed contract shape

```yaml
source:
  format: parquet
  artifact_root: taya_run
  path: canonical-parquet/experiments.parquet
```

Machine-local configuration supplies the absolute `taya_run` location.

## Work sequence

1. Specify root names, path semantics, and resolution precedence.
2. Add backward-compatible contract model fields and resolver tests.
3. Route ingestion exclusively through the resolver.
4. Add a portability audit command or diagnostic section.
5. Migrate repository contracts and documentation.

## Acceptance criteria

- The same contract digest is produced on two machines with different artifact
  root locations.
- A relocated canonical run ingests without editing its contract.
- Unknown roots and path traversal fail before any catalog mutation begins.
- Operational records retain the actual resolved source and checksum.
- Existing absolute-path contracts continue to load for the documented
  deprecation interval.

## Non-goals

- Downloading artifacts from remote object stores.
- Bundling data into Git.
- General secrets management beyond local configuration.

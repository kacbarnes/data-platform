# v0.5 implementation plan: Container portability

## Objective

Support Docker Compose and Podman Compose as explicit, behaviorally tested
container backends without aliases or hidden command substitution.

## Scope

### Backend abstraction

- Define a small interface for availability, Compose command construction,
  startup, shutdown, status, logs, and profile execution.
- Select a backend through an explicit setting or deterministic capability
  detection.
- Report the selected executable, Compose provider, rootless/rootful mode, and
  version through `lake platform doctor`.

### Compose portability

- Keep a standards-oriented base `compose.yaml`.
- Generate or maintain minimal backend overrides only for demonstrated
  differences.
- Handle Podman user namespaces and bind-mount ownership deliberately.
- Validate localhost endpoints under Docker, Podman on Linux/WSL, and
  container-VM hosts where supported.

### Storage safety

- Preflight the effective host/container UID mapping before service startup.
- Never solve permission failures by recursively broadening warehouse access.
- Document bind mounts, named volumes, and WSL ext4 storage tradeoffs.

## Work sequence

1. Capture current Docker behavior as backend contract tests.
2. Implement backend discovery and explicit selection.
3. Add Podman Compose support and rootless diagnostics.
4. Isolate the smallest required Compose differences.
5. Test bootstrap, restart, persistence, and read/write behavior on both
   engines.

## Acceptance criteria

- The same lifecycle commands operate a fresh Docker or Podman installation.
- No documentation recommends aliasing `docker` and `podman`.
- Restarting either backend preserves PostgreSQL and Iceberg state.
- An existing Iceberg table remains readable and a temporary integration table
  can be created through the client on both backends.
- Unsupported Compose providers fail with a precise version/capability error.

## Non-goals

- Kubernetes deployment.
- Treating Docker and Podman internals as identical.
- Migrating live container-engine storage automatically.

# v0.7 implementation plan: Export and migration

## Objective

Create a verifiable, credential-free transfer package that can reconstruct a
published dataset on another initialized platform.

## Public command target

```text
lake export create <collection-or-dataset>
lake export verify <archive>
lake import plan <archive>
lake import apply <archive>
```

## Scope

### Transfer manifest

- Define a versioned manifest containing platform version, contracts, source or
  canonical artifact inventory, checksums, row counts, dataset versions,
  quality summary, Git provenance, and publication receipts.
- Explicitly exclude `.env`, SSH material, container storage, PostgreSQL files,
  control-database files, and the Iceberg warehouse.
- Distinguish reproducibility inputs from optional convenience outputs such as
  workbooks.

### Export

- Support ZIP for Windows interoperability and a documented tar format where
  appropriate.
- Stream checksums and produce a top-level checksum for the archive.
- Offer source-inclusive and canonical-only profiles with clear semantics.

### Import

- Verify all bytes before planning catalog mutations.
- Map artifact roots and show target datasets, collisions, and required
  update/recovery flags.
- Re-ingest through the normal platform client so every mutation is tracked.
- Treat new Iceberg snapshot IDs as expected while comparing invariant hashes,
  row counts, identifiers, and validation outcomes.

## Work sequence

1. Specify and version the manifest schema.
2. Implement deterministic inventory and credential-exclusion tests.
3. Implement export creation and verification.
4. Implement dry-run import planning.
5. Implement tracked reconstruction and post-import comparison.
6. Test a round trip between isolated local platform instances.

## Acceptance criteria

- A package exported on one supported host reconstructs the same canonical
  relations on another host.
- Archive verification detects missing or modified files before mutation.
- A secret-scanning test proves known local credentials are absent.
- Import never copies warehouse or database internals.
- Import collisions fail safely and require explicit resolution.
- The new publication receipt links original provenance to new snapshot IDs.

## Non-goals

- Byte-for-byte replication of Iceberg snapshots.
- Live database replication.
- Using OneDrive or another sync provider as the active warehouse.

# v0.8 implementation plan: Compatibility automation

## Objective

Turn portability claims into repeatable evidence across supported operating
environments, installation methods, and container engines.

## Scope

### Test matrix

- Run unit and packaging tests on supported Python versions.
- Exercise clean installation, configuration resolution, contract resolution,
  lifecycle command construction, and export verification on Linux and
  Windows runners.
- Run live disposable integration tests where Docker or Podman is available.
- Qualify WSL 2 explicitly for storage, permissions, localhost networking, and
  restart persistence.

### Test fixtures and safety

- Use temporary data roots, unique catalog/namespace names, and synthetic data.
- Never connect automated tests to the user’s live Polaris catalog.
- Remove temporary catalog objects through the catalog API after successful
  tests and record cleanup failures.
- Cache images and dependencies without caching credentials or mutable state.

### Compatibility reporting

- Publish a support matrix naming tested versions and known limitations.
- Record the container engine, Compose provider, filesystem type, and platform
  adapter in diagnostic output and bug reports.
- Add a release qualification checklist for environments not continuously
  available in CI.

## Work sequence

1. Separate hermetic unit tests from optional live integration tests.
2. Add clean-build and wheel-install jobs.
3. Add Docker and Podman matrices on Linux.
4. Add Windows launcher and WSL qualification coverage.
5. Add documented macOS/container-VM smoke qualification.
6. Publish compatibility results as release artifacts.

## Acceptance criteria

- Required Linux and packaging jobs gate every merge.
- Docker and Podman integration jobs prove create/read/restart behavior using
  disposable state.
- WSL 2 has a reproducible release qualification procedure and passes it.
- Documentation distinguishes first-class, supported, and experimental hosts.
- Test logs contain no credentials and leave no live catalog mutations.

## Non-goals

- Claiming support for an untested host/runtime combination.
- Performance parity across SSD, HDD, WSL-mounted, and native filesystems.
- Large-scale distributed-load testing.

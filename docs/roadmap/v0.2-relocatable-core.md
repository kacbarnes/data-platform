# v0.2 implementation plan: Relocatable core

## Objective

Make a cloned checkout operate from any user-owned directory without editing
committed files or assuming `/home/kent`, Miniforge, or a particular shell.

## Scope

### Repository and executable discovery

- Derive the project root from the installed package, an explicit
  `--project-root`, or `DATA_PLATFORM_HOME` in a documented precedence order.
- Discover Python and DuckDB capabilities from the active environment instead
  of fixed executable paths.
- Replace thick Bash behavior with Python; retain only thin compatibility
  launchers where useful.

### Machine-local configuration

- Define a typed settings model for project, data, state, and endpoint paths.
- Support environment variables and a private local configuration file.
- Expand user paths and resolve relative paths against a documented base.
- Generate credentials without printing them and enforce restrictive file
  permissions where the host supports them.

### Diagnostics

- Add a read-only configuration diagnostic showing resolved non-secret values,
  their source, and missing prerequisites.
- Detect unwritable directories before starting services or ingestion.
- Replace user-specific error messages with generated commands and paths.

## Work sequence

1. Inventory committed absolute paths and classify runtime paths versus
   historical documentation.
2. Introduce the settings model and path-precedence tests.
3. Migrate Python modules and scripts to the settings model.
4. Make launchers derive their own location or call the installed entry point.
5. Update examples and documentation, retaining no real local credential.
6. Test from a temporary checkout whose path contains spaces.

## Acceptance criteria

- A repository-wide check finds no `/home/kent` runtime dependency.
- Unit tests cover explicit configuration, environment overrides, defaults,
  relative paths, spaces, missing files, and unwritable locations.
- `lake datasets`, `lake status`, and CLI help run from outside the repository.
- A fresh temporary checkout can initialize configuration without modifying a
  tracked file.
- Existing control metadata and catalog behavior remain backward compatible.

## Non-goals

- Portable dataset source references; that belongs to `v0.3`.
- Full service lifecycle orchestration; that belongs to `v0.4`.
- Supporting more than one container engine.

## Risks and mitigations

- **Ambiguous precedence:** document and test one order for CLI flags,
  environment, local config, and defaults.
- **Secret disclosure:** expose only whether a secret exists, never its value.
- **Shell regressions:** keep compatibility wrappers until Python replacements
  have equivalent smoke tests.

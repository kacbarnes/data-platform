# v1.0 implementation plan: Stable platform contract

## Objective

Declare a dependable public interface for local research lakehouse operation,
with documented compatibility, upgrades, recovery, and release provenance.

## Scope

### Stable interfaces

- Freeze and document command names, exit-code classes, JSON output envelopes,
  configuration keys and precedence, contract schema, artifact-root semantics,
  and transfer-manifest schema.
- Define deprecation periods and compatibility guarantees.
- Version machine-readable schemas and provide validation commands.

### Upgrade and recovery

- Test upgrade paths from each supported pre-`v1.0` release state.
- Keep control-database migrations forward-only, numbered, and recoverable from
  documented backups.
- Add pre-upgrade diagnostics and post-upgrade verification.
- Document recovery for interrupted ingestion, existing untracked tables,
  failed service bootstrap, and unavailable source artifacts.

### Release engineering

- Maintain a changelog and migration guide.
- Build checksummed wheels, source archives, and optional standalone artifacts.
- Produce a software bill of materials and dependency/security scan results.
- Tag releases and record the exact container image versions or digests.

### Operational documentation

- Provide fresh-install, routine-operation, backup, restore, transfer, upgrade,
  and troubleshooting guides.
- Document what is authoritative in source storage, Iceberg, Polaris,
  PostgreSQL, and the control database.

## Work sequence

1. Audit public behavior and resolve remaining provisional interfaces.
2. Publish versioned JSON/YAML schemas and compatibility policy.
3. Exercise upgrade and recovery fixtures from representative prior states.
4. Complete operator documentation and support matrix.
5. Produce and independently install a release candidate.
6. Run a complete ingest, test, export, and reconstruction qualification.

## Acceptance criteria

- Fresh installation succeeds on every first-class target using only published
  instructions and artifacts.
- Upgrade fixtures preserve dataset versions, quality results, lineage, and
  existing Iceberg readability.
- All stable JSON responses and configuration/manifest schemas have contract
  tests.
- Release artifacts are checksummed, credential-free, reproducible where
  practical, and traceable to a Git tag.
- End-to-end qualification reconstructs a canonical collection with matching
  invariant hashes and row counts.
- Known limitations and support boundaries are explicit.

## Deferred decision: native launcher

After the stable contract is proven, measure installation friction, startup
cost, binary size, and maintenance burden. A Rust launcher may be proposed if
it produces a clear improvement while preserving `v1.0` behavior. Rewriting
data operations is not justified by portability alone.

## Non-goals

- Distributed orchestration or managed-cloud operation.
- Guaranteed compatibility with every S3-compatible service.
- A C implementation.
